# Mídia no chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A conversa viva mostra e envia imagem, áudio, vídeo e documento. A mídia que chega é baixada para o R2 depois do notify, sem segurar a bolha.

**Architecture:** A página `src/app/(dashboard)/inbox/page.tsx` ganha um input de arquivo e desenha a bolha a partir de um modelo puro. O envio reusa `POST /api/whatsapp/send` com `message_type` em `image | audio | video | document` e `media_url` público (upload já existente em `/api/storage/upload`). No inbound, a bolha nasce com o texto ou o marcador; o binário vai para o R2 em seguida e um notify `UPDATE` preenche `mediaUrl`.

**Tech Stack:** Next.js 16, WAHA `sendImage` / `sendFile`, R2 `uploadObject`, Vitest.

## Global Constraints

- Um app Next.js na raiz. Domínio em `src/domain`. Sem segundo serviço (ADR 004).
- Tipos aceitos neste ciclo: `image`, `audio`, `video`, `document`. Reação, citação e template picker continuam de fora.
- A bolha de texto não espera o download da mídia. `settleInboundMedia` roda em `void` depois do `notifyAccount` do insert.
- Arquivo maior que o limite de `MEDIA_MAX_BYTES_BY_KIND` em `src/domain/storage/upload-media.ts` é recusado no cliente antes do POST.
- URL pública da mídia recebida é a devolvida por `uploadObject` (`src/domain/storage/r2.ts`). Não gravar a URL interna do WAHA como `mediaUrl` definitivo. Pode gravar `null` no insert e preencher no update.
- `sendImage` só para `image`. `audio`, `video` e `document` usam `sendFile` (já é o ramo de `sendMessageToConversation`).
- Não mudar `phonesMatch`, `nameLocked` nem o contrato do SSE além de preencher `mediaUrl` no update.

- [ ] **Step 3: Write minimal implementation**

```ts
const MEDIA = ['image', 'audio', 'video', 'document'] as const
type MediaKind = (typeof MEDIA)[number]

export function messageBubble(message: {
  content_type: string
  content_text: string | null
  media_url?: string | null
}): {
  kind: 'text' | MediaKind
  text: string | null
  url: string | null
} {
  const url = message.media_url ?? null
  const kind = MEDIA.find((item) => item === message.content_type)
  if (kind && url) {
    return { kind, text: message.content_text, url }
  }
  return { kind: 'text', text: message.content_text, url: null }
}
```

Na página da inbox, no lugar de `{m.content_text || `[${m.content_type}]`}`:

- `kind === 'image'`: `<img src={url} alt={text ?? 'imagem'} className="max-h-64 rounded-md" />` e, se houver `text` que não seja só `[image]`, um parágrafo abaixo.
- `kind === 'audio'`: `<audio controls src={url} />`
- `kind === 'video'`: `<video controls src={url} className="max-h-64 rounded-md" />`
- `kind === 'document'`: `<a href={url} target="_blank" rel="noreferrer">{text || 'documento'}</a>`
- `kind === 'text'`: o texto, ou `[${m.content_type}]` se o texto vier vazio.

Implementar as duas funções puras.

`downloadWahaMedia` faz `fetch(url, { headers: headers() })`. Se `!res.ok`, lança `Error` com `WAHA media ${res.status}`. `contentType` é `res.headers.get('content-type')` sem parâmetros, ou `application/octet-stream`. Body é `Buffer.from(await res.arrayBuffer())`.

`settleInboundMedia` em `inbound-media.ts`:

```ts
export async function settleInboundMedia(args: {
  accountId: string
  messageId: string
  conversationId: string
  mediaUrl: string
  mimetype: string | null
  session: string
}): Promise<string> {
  const file = await downloadWahaMedia({
    url: args.mediaUrl,
    session: args.session,
  })
  const key = inboundMediaKey(
    args.accountId,
    args.messageId,
    args.mimetype || file.contentType,
  )
  const publicUrl = await uploadObject({
    key,
    body: file.body,
    contentType: args.mimetype || file.contentType,
  })
  await prisma.message.update({
    where: { id: args.messageId },
    data: { mediaUrl: publicUrl },
  })
  await notifyAccount({
    table: 'messages',
    op: 'UPDATE',
    id: args.messageId,
    accountId: args.accountId,
    conversationId: args.conversationId,
    mediaUrl: publicUrl,
    contentType: args.mimetype ?? undefined,
  })
  return publicUrl
}
```

No ingest, o insert grava `mediaUrl: null` quando `payload.hasMedia` (não a URL do WAHA). Depois do notify do insert:

```ts
if (session && payload.hasMedia && payload.media?.url) {
  void settleInboundMedia({
    accountId,
    messageId: message.id,
    conversationId,
    mediaUrl: payload.media.url,
    mimetype: payload.media.mimetype ?? null,
    session,
  }).catch((err) => console.warn('[settleInboundMedia]', err))
}
```

O payload SSE do insert leva `mediaUrl: null` nesse caso. O update leva a URL pública.

No cliente (`apply-realtime`), um `op === 'UPDATE'` com `mediaUrl` e sem `movedFromConversationId` atualiza `media_url` da mensagem com aquele `id` no cache da `conversationId`. Acrescentar `applyMediaUrl` e um teste: a mensagem `msg-1` passa a ter `media_url: 'https://cdn.example/a.jpg'`.
