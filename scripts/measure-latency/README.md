# Latency measurements

This collector is not wired into the application. Instrument the browser, server and phone observer separately before claiming measured end-to-end timings. It never stores message text, audio, credentials, URLs or raw identifiers: use `opaqueId(value, secret)` with a random secret at least 32 characters long, shared only by the trusted instrumentation and kept out of files and logs. A stable HMAC enables correlation of account, local ID and remote ID; do not use a real credential as the secret. The collector accepts only the documented fields and HMAC values. Identifiers can still be linkable metadata: restrict file access and delete it after analysis.

Call `recordMeasurement(path, { metric, kind, account, localId, remoteId, attempt, outcome, durationMs, clipDurationMs })` from trusted instrumentation. `metric` is one of `click_to_local_bubble`, `send_to_provider_accept`, `webhook_to_second_screen`, `accept_to_phone_receipt`, `audio_upload`, `audio_convert`, `audio_clip_duration`. `kind` is `text` or `audio`, `outcome` is `success` or `failure`, `attempt` starts at 1. `remoteId` is optional until known; `clipDurationMs` is optional and audio-only. Record one terminal measurement per account/local ID/attempt/metric, including failures and timeouts; missing observations must be reported separately and never silently treated as successes. Success requires a duration in milliseconds; failure can omit it. `audio_clip_duration` records clip duration as `durationMs`. Do not overwrite an earlier remote ID with unverified information.

Use monotonic elapsed time for measurements on a single clock. Cross-device webhook-to-screen and provider-to-phone measurements require synchronized clocks with measured uncertainty, or a common observer; do not subtract unrelated monotonic clocks. Record the clock method, uncertainty, network, device, provider and test period outside the JSONL without sensitive data. Record each stage independently, including upload, conversion and clip duration. The phone receipt must be observed on a real online phone; provider acceptance is not phone delivery.

Run `node scripts/measure-latency/cli.mjs measurements.jsonl`; it prints only aggregates. p50/p95 use nearest rank over successful observations. Failure rate is failures divided by terminal observations for that metric, not all started operations; disclose unobserved operations separately. Duplicates and unknown fields fail closed. Initial targets: local bubble p95 <= 100 ms, text webhook to second screen p95 <= 500 ms, text provider acceptance p95 <= 2 s. No phone delivery or audio threshold is assumed. Compare equivalent conditions and collect at least 100 texts and 30 audio clips per duration across periods before release. The tool does not generate traffic, validate clocks, or verify that measurements represent real delivery.

Self-test: `node --test scripts/measure-latency/measure.test.mjs`.
