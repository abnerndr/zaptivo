# WhatsApp acceptance gate

The tests in `whatsapp.test.ts` specify the staging observations required for sections 7 and 8. Run with `node node_modules/vitest/vitest.mjs run --config tests/acceptance/vitest.config.ts`. The suite skips without `WHATSAPP_ACCEPTANCE_DRIVER`; skipped is **blocked**, never a pass. The default repository Vitest config excludes this directory. A real driver has not been supplied: no live environment, test accounts, two authorized browsers, second organization, provider access or online test phones were available for this run.

For a pilot, implement a local staging-only ES module and set `WHATSAPP_ACCEPTANCE_DRIVER` to its absolute path. Export `async function createDriver()` returning `{ async run(scenario) { ... } }`. Each scenario must perform the real actions named by the test and independently obtain observations from the application, database, provider and/or phone, returning the fields asserted in the test. It must isolate accounts, use disposable data, safely restore configuration, and avoid recording message contents, audio, tokens or credentials. Record evidence and failed operations separately; do not return invented values or substitute mock fixtures for phone, browser, database or provider observations. Use two webhook URLs, two accounts, at least two authorized sessions, a viewer, the actual agent, and a separate online phone. Simulate process termination at the actual persist/publish boundary. Test migration and rollback against an isolated database copy and a disposable pilot provider account, suspending sends and reconciling uncertain attempts before each switch. Do not target production.

The assertions express required outcomes, not an implementation of the staging driver. They cannot prove integration in its absence. Keep phone receipt, clock uncertainty, missing samples and operational logs in the test report. For migration schema validation also follow `prisma/migrations/20261105000000_whatsapp_provider_per_account/VALIDATION.md`; schema backfill alone is not provider migration or rollback.
